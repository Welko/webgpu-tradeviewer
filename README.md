# Trade Viewer

A C++ WebGPU viewer for Binance BTC/USDT market data. It builds to WebAssembly with Emscripten and is hosted in a React page. It also runs natively.

Status: scaffold only. The viewer creates a WebGPU device and clears the surface each frame.

## Layout

```
cpp/
  modules/Core       no WebGPU dependency, header-only (INTERFACE) for now:
                       Core/Log.hpp   logging
                       Core/Data/     market data (parsing, book reconstruction) — coming
  modules/Graphics   WebGPU. Public API is only Renderer (a facade with no WebGPU types).
                     Context (device, surface...) and future draw layers are internal (src/include).
  apps/Viewer        App (resize/update/render) + entry points:
                       NativeMain.cpp  GLFW window and loop
                       WebMain.cpp     embind `Viewer` class, loop driven by JS
web/                 Vite + React + TypeScript
  src/viewer/        createViewer() and <ViewerCanvas>
  src/wasm/          generated by the Emscripten build (gitignored)
```

The platform side owns the frame loop: `requestAnimationFrame` on the web, a GLFW loop natively. Each frame it calls `update(nowMs)` (CPU state) and then `render()` (draw only). WebGPU init uses plain callbacks, so the same code runs on both platforms without Asyncify.

## Requirements

- CMake ≥ 3.24 and a C++23 compiler (tested with GCC 13)
- Node 18+
- [emsdk](https://emscripten.org/docs/getting_started/downloads.html) (tested with Emscripten 6.0.13)
- Native on Linux: `sudo apt install libxkbcommon-dev libx11-dev libxrandr-dev libxinerama-dev libxcursor-dev libxi-dev`
- A browser with WebGPU

The first configure downloads WebGPU-distribution (wgpu-native or emdawnwebgpu) and GLFW.

## Web

```bash
source ~/emsdk/emsdk_env.sh
cd web
npm install
npm run dev        # builds the wasm, then starts Vite on http://localhost:5173
```

`npm run build:wasm` rebuilds only the C++ part. Vite reloads when `src/wasm/` changes.

## Native

```bash
cd cpp
cmake --preset native
cmake --build --preset native
./build/native/apps/Viewer/Viewer                          # or --gpu=low-power / --gpu=high-performance
```

## Choosing the GPU

The web can't list GPUs. It can only send a `powerPreference` hint when it requests an adapter. The page has a GPU selector that recreates the viewer with that hint. The browser may ignore it (on Windows, the OS graphics settings usually decide). What a browser reveals about the WebGPU adapter varies. Some give `vendor` and `architecture` (for example `intel gen-9`). Others give nothing. Few give the exact device. When the browser reveals none of these, the viewer falls back to the renderer string WebGL reports. That is usually more detailed, but it may name a different GPU on multi-GPU machines.
